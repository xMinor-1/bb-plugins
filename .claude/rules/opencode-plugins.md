# Плагины OpenCode 2 и ключи: что проверено на 2.2.5

- Ключ подставлять в хуке `http.request`, а не `model.request`: только в нём есть
  настоящий `Request` с URL. Заголовок ставить, лишь если origin запроса равен
  origin `baseURL` из манифеста: проектный `opencode.json` чужого репо может
  переопределить `baseURL` провайдера, и ключ уйдёт туда. Так было в fleet-kit
  до ревью PR #41 (31.10.2026).
- Запрос с подставленным ключом пересобирать с `redirect: "error"`: иначе `fetch`
  идёт за 3xx шлюза и несёт заголовок на второй адрес. Подстановки `{env:}`,
  `{file:}` проверять и в ключах объектов (`headers: {"x-{env:TOKEN}": "1"}`),
  а не только в значениях. Оба пропуска нашло ревью fleet-kit 0.1.0 (31.10.2026).
- У плагина OpenCode нет логгера, а `console.warn` под bb не попадает никуда
  (stderr OpenCode bb отбрасывает). Предупреждения писать своим файлом в каталог
  журналов OpenCode: `~/.local/share/opencode/log/<плагин>.log`, без значений ключей.
- Плагин OpenCode из сгенерированной строки: `\n` внутри TS-шаблона превращается
  в перевод строки в JS. Писать `\\n`, проверять импортом файла в тесте.
- bb CLI превращает `--<опция>-stdin` в `--<опция> <значение>` до вызова плагина.
  Запретить ввод значения аргументом нельзя, только скрыть опцию (`hidden: true`)
  и не упоминать её в справке и README.
- MCP в OpenCode 2: `mcp.servers.<имя>` = `{type: "remote", url, headers, oauth, timeout: {startup,
  catalog, execution}}` (мс); старый вид `mcp.<имя>` помечен deprecated. `{file:/абс/путь}` в
  заголовке работает целиком и частью (`Bearer {file:…}`), перевод строки в файле срезается, пробел в
  пути не мешает. Нет файла — предупреждение в журнале и пустой заголовок, остальные серверы живы.
- `opencode mcp list --standalone` к MCP не подключается: проверять через фоновую службу
  (`opencode mcp list` без флага) и журнал заглушки. Служба следит за `opencode.json` и сразу
  открывает и закрывает сессии MCP при правке; за файлами по `{file:}` не следит (mcp-catalog, 31.10.2026).
