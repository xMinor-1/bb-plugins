# Долгие вызовы bb SDK и состояние между сверками

- Таймаут через `Promise.race` не отменяет вызов: `plugins.install` идёт в bb
  дальше. После таймаута не ставить другой источник с тем же id — сверить
  `plugins.list` и `installJobs.list` и, если неясно, отложить до следующего прохода.
  В fleet-kit 0.1.0 откат шёл параллельно незавершённой установке (31.10.2026).
- Действие, которое снимает плагин (смена источника), — с лимитом попыток в
  сохранённом состоянии: иначе неудача повторяется на каждой сверке и каждый раз
  стирает секретные настройки. Секреты после переустановки — уведомлением.
- `experimental_startUpdate` возвращается сразу, обновление идёт задачей. Повторный
  проход до перезапуска видит то же предложение: проверять
  `experimental_updateJobs.list()` и не засчитывать попытку, пока задача queued/running.
- Удаляя каталог-замок, сверять не только inode: ФС сразу отдаёт тот же inode и
  тот же `birthtime`. Переносить в сторону и проверять владельца по содержимому.
