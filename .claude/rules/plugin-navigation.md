# Переход на страницу другого плагина

- `useBbNavigate().toPluginPanel` ведёт только на панели своего плагина, `openUrl`
  открывает браузер. Страницу чужого плагина (`/plugins/<id>/<панель>`) внутри bb
  открывать так, как это делают ссылки самого bb (react-router):
  `history.pushState({ usr: null, key, idx: prev.idx + 1 }, "", path)` и затем
  `dispatchEvent(new PopStateEvent("popstate"))`. Готовая функция — `openBbPage` в
  `plugins/fleet-kit/src/app/setup-page.tsx`, проверена в docker на bb 0.48.1:
  открывает страницу почты, «Назад» возвращает (fleet-kit 0.3.0, 31.10.2026).
- Путь, который пришёл от другого плагина, проверять регуляркой
  `^/plugins/[a-z0-9][a-z0-9-]*(/[A-Za-z0-9._~-]+)*$`: никаких внешних адресов и `..`.

# Внешний браузер

- `useBbNavigate().openUrl` в bb 0.48 открывает ссылку по настройке клиента «Open links in the
  in-app browser» (ключ `bb.openLinksInAppBrowser`, по умолчанию включён): в настольном приложении —
  встроенный браузер bb, у которого нет входа в рабочие системы. Явного «открыть снаружи» в SDK нет.
- Ссылку, которая должна уйти в браузер человека (трекер, корп-системы с входом), открывать через
  `window.bbDesktop.openExternalUrl(url)` — им пользуется кнопка «во внешнем браузере» самого
  встроенного браузера, — с запасным `openUrl` для веб-версии и на случай, если мост сменится:
  `openInOwnBrowser` в `plugins/tracker-board/src/app/links.ts`. Схему проверять: только http(s).
  В tracker-board задача из панели открывалась во встроенном браузере без входа в трекер (07.11.2026).
