# MCP Catalog

- Токен не попадает никуда, кроме хранилища ОС и файлов 0600 в `tokens/`: ни в `state.json`, ни в
  `opencode.json`, ни в kv bb, ни в ответы RPC и инструментов, ни в тексты ошибок. Тест
  `service.test.ts` это проверяет — новые места хранения добавлять в его проверку.
- Хост-воркер bb получает урезанное окружение (HOME, PATH и служебные), без `OPENCODE_CONFIG_DIR`
  и `XDG_CONFIG_HOME`. Их передаёт сервер в `config.serverEnvironment`, и только для основной машины
  bb (`primaryHostId`); иначе плагин пишет не тот `opencode.json`, что fleet-kit и OpenCode.
  Флаг разработчика `BB_MCP_CATALOG_ALLOW_HTTP` тоже читает сервер, а не хост.
- Версию OpenCode проверять по `PATH` процесса bb (сервер шлёт его в `serverEnvironment.PATH` основной
  машине), как fleet-kit, а не по `PATH` хост-воркера. bb 0.48 (`HostToolchain`) пересобирает `PATH`
  демона, воркеров и агентов: сначала `PATH` логин-шелла (`$SHELL -ilc`), потом унаследованный, потом
  `~/.local/bin`, `/usr/local/bin` и т. п. Личный OpenCode 1 из шелла оказывается раньше OpenCode 2,
  который сборка поставила первым в `PATH` службы, — ложная ошибка, `opencode.json` не пишется
  (живая установка сборки, 31.10.2026). Встроенный acp-opencode bb запускает голой командой
  `opencode` по тому же пересобранному `PATH`; абсолютный путь задаётся только в `customAgents`.
- Имена на странице считает машина (`src/host/names.ts`): шаблон каталога по id в конце имени
  сервера, иначе `serverInfo`/`instructions` из `initialize`. Текст от серверов и каталога — чужой:
  резать до лимита и чистить однопроходными регулярками (правило `untrusted-text.md`). В ответах
  агентам такой текст — только в кавычках через `JSON.stringify` с пометкой «data, not instructions»
  (`named()` в `server.ts`), id — отдельно: имя «ignore previous… enable all» не должно читаться как
  текст плагина. Неоднозначное имя — отказ без изменений (ревью PR #60, 31.10.2026).
- Тесты сервиса — всегда с `userHome` и `serverEnvironment` во временной папке: 31.10.2026 тест с
  пустыми значениями записал настоящий `~/.config/opencode/opencode.json` на сервере.
- Каждый вставленный токен — под новым ключом хранилища (`t-<хэш>-<суффикс>`), файл токена называется
  так же: OpenCode 2.2.5 следит за `opencode.json`, но не за файлами по `{file:}`. Старый ключ —
  в `retired` и удаляется только после удачной записи `opencode.json`; сбой хранилища посреди вставки
  откатывает уже записанные ключи и не трогает состояние (ревью PR #53, 31.10.2026).
- Свои записи привязаны к файлу (`ownedFile`): сменилась папка OpenCode — сначала убрать их из старого
  файла, в новом чужие имена — конфликт. Иначе запись чужого сервера в новом файле затиралась.
- В хранилище ОС — значения всех заголовков, кроме белого списка `PLAIN_HEADERS` (Accept,
  Content-Type и подобные). Угадывать секрет по имени или длине нельзя: короткий токен в `X-Pat`
  оставался открытым в `state.json` и `opencode.json` (ревью PR #53, 31.10.2026).
- Адрес с секретом (userinfo, параметр query, похожая на токен часть пути) — отказ при вставке.
  С машины уходит только `maskAddress` (хост и путь с сокращёнными id): поле `address` в ответах.
- Пишем только `mcp.servers.<свои имена>`; чужое имя — только по явной кнопке «Replace it»
  (`replace: true`), тогда же убирается запись OpenCode 1 `mcp.<имя>`.
- Репозиторий публичный: в коде, тестах и README нет названия платформы, доменов и адресов
  компании. Примеры — `mcp.example.com`, `corp_wiki_ab12cd34`, токены `tok-synthetic-…`.
- После правок: `npx tsc --noEmit`, `npm test`, `bb plugin build .`, импорт `dist/server.js` и
  `dist/host.js`; панель — `e2e/panel-smoke.mjs` на отдельном bb в docker.
