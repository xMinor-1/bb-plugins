# BB Plugins — правила репозитория

Монорепозиторий плагинов [bb](https://getbb.app). Все собственные плагины живут
здесь, а не в рабочем каталоге окружения bb.

## Новый плагин

```sh
scripts/new-plugin.sh <имя> [--app]
```

Скрипт создаёт `plugins/<имя>` через `bb plugin new` и регистрирует его в
`.bb/plugins.json`. Дальше руками:

1. `npm install` в директории плагина.
2. Заполнить в `package.json` → `bb`: `name`, `description`, `branding.icon` —
   иконка из набора bb или своя `./icon.svg`, не оставлять скаффолдный `Zap`.
3. Написать `README.md` рядом с кодом: что делает, установка, как устроено.
4. Добавить строку в таблицу корневого `README.md`.
5. Проверить: `npx tsc --noEmit` и `bb plugin build .` — оба без ошибок.
6. Закоммитить и запушить, иначе установка из git не увидит плагин.

## Язык

Всё, что видят пользователи плагина, — по-английски: строки интерфейса,
`bb.description`, README плагина, комментарии в коде. Каталог плагинов bb
международный, и ревью там читают английский код. По-русски — только этот файл
и корневой `README.md`: они внутренние.

## Никогда

- Не создавать плагины в `~/.bb/personal-workspaces/env_*` — эти окружения
  удаляются вместе с тредом, вместе с кодом. Так уже терялся `theme-toggle`,
  восстанавливали из транскриптов сессий.
- Не коммитить `dist/` и `node_modules/` — bb собирает плагин при установке сам.
- Не выносить рабочие зависимости в `devDependencies`: всё, что импортирует код,
  должно быть в `dependencies`, иначе плагин не поставится из git. Исключение —
  то, что bb шимит в рантайме (react, portal-примитивы, `@get-bb/plugin-sdk`,
  `sonner`), и типы для тайпчека (`@types/*`, `better-sqlite3`, `hono` — их
  требуют бандл-типы SDK).

## Установка и разработка

Плагин из этого репозитория ставится по пути — тогда правки живые:

```sh
bb plugin install path:"/home/coder/Work/3. projects/BB Plugins" --plugin <имя> --yes
bb plugin dev plugins/<имя>     # пересборка и перезагрузка на каждое сохранение
```

Смена источника установленного плагина только через снятие:
`bb plugin remove <имя>` (для path-установок файлы остаются на месте), затем
`bb plugin install ...`.

## Структура

```
.bb/plugins.json      индекс плагинов для bb plugin install --plugin <имя>
plugins/<имя>/        один плагин = одна директория со своим package.json
scripts/new-plugin.sh создание нового плагина с регистрацией в индексе
```
